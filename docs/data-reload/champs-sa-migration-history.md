# Champs/Summer Awards history migration — full history (August 2026)

Extracted from Project Instructions on 2026-07-30 for length management. See CLAUDE.md / Project Instructions "Data files" section for the current, authoritative status of `league-results-history-v2.json`, `relay-results-history-v2.json`, and the `data/archive/` legacy files.

Initiated after Wade located and uploaded historical Champs/Summer Awards meet PDFs into `data-source-pdfs/<year>/` directories. A Planner inventory pass found usable individual-results PDFs for three meets — **2024 Champs (AM+PM session split), 2025 Champs (single combined file), 2026 Summer Awards (single combined file)** — plus several team-scores-only PDFs (no individual rows, not parsed) and confirmed several meets have **no recoverable source PDF at all: 2022 Champs individual results, 2022 Summer Awards (any), 2023 Champs (any), 2023 Summer Awards (any), 2024 Summer Awards individual results.** These five are permanently unrecoverable, not a gap to re-investigate later.

## Round 1 — wrong-file mistake (commit 9c833d8)

A Coder task was specified with the filenames `league-results-history.json`/`relay-results-history.json` — at the time these were still the plain (non-archived) legacy filenames, easily confused with the authoritative `-v2` files. Coder correctly parsed and validated 3,844 individual + 172 relay rows (fixing a real parser gap along the way — a "VC"/VPSU-Championship-Record achievement suffix in the 2025 Champs PDF that had been silently mishandled, requiring a targeted `pdf-reload-parser.mjs` fix plus new regression tests, 635→645 passing), but wrote them into the wrong (legacy) files. Reviewer signed off and it was pushed before the mistake was noticed. **No data was lost or corrupted — it was correctly parsed, just in the wrong destination.**

## Round 2 — migration to v2 (commits 032b078, 6b3b7f9)

The 3,844+172 rows were reshaped into v2 schema and copied into `league-results-history-v2.json`/`relay-results-history-v2.json`, leaving the legacy files untouched (byte-identical, SHA256-verified) as a non-destructive first pass. A field-mapping table was built and reviewed before writing: most fields copied directly, `meetType`/`qualifyingSwim` added as new v2 extensions, `sourcePdf`/`sourceEventNumber`/`verifiedAgainst`/`plausibilityFlags` set to null/`[]` where unrecoverable from the legacy rows.

**First relay ageGroup mapping attempt was wrong**: Coder collapsed all 10 legacy relay ageGroup labels (both true "Men/Women Open" relays and genuine age-specific brackets like "Girls 9-10") down to just two v2-looking values (`Boys 9-18`/`Girls 9-18`), based on an unverified assumption that v2's relay convention only had two values. This was caught before Reviewer and corrected (commit 6b3b7f9): Step 1 of the fix directly inspected `relay-results-v2.json` and found it actually already uses 11 distinct granular labels (`Boys/Girls 8&Under, 9-10, 11-12, 13-18, 9-18`, `Mixed 9-18`) — the original ageGroups were restored from the untouched legacy source by index alignment (0 mismatches), and this restoration is what surfaced that `waves-record-progression` (which reads this file) would otherwise have silently failed to match any age-specific Champs relay row to a record key.

Reviewer (full 9-item checklist) then confirmed: full 172-row diff against legacy source (172/172 pass), 9 independent individual spot-checks including DQ and qualifyingSwim rows, zero leakage of `meetType`/`qualifyingSwim` onto pre-existing rows, correct null/`[]` provenance fields with no consumer assuming them non-null, legacy files still byte-identical, a **live run** confirming `waves-record-progression` now correctly reconstructs 3 previously-"unreconstructable" relay progressions (Women Open 200m Medley Relay: 2 steps; Men Open 200m Medley Relay: 1 step; Men Open 200m Freestyle Relay: 1 step, also the current team record), 645/645 tests, clean git history.

One **SHOULD FIX, non-blocking** finding: the migrated rows' "Men Open"/"Women Open" labels are internally inconsistent with the 2,071 pre-existing regular-season rows' "Boys/Girls 9-18" labels for the same Open bracket — flagged, not fixed, since it's a pre-existing v2-relay-convention gap, not something this migration introduced (and the migration's choice objectively improved record-matching, per the live-run evidence above).

## Round 3 — legacy file archival (commit 5b41d65, in two sub-steps)

With the correct data now safely in v2, the legacy files that caused the original mistake were archived to prevent recurrence. A first authority-check pass found `scripts/parse-champs-history.mjs` still had live `readFileSync` calls against `league-results-history.json`/`relay-results-history.json` (it reads existing rows before appending) — archiving was correctly **blocked** at this point rather than proceeding around a live reference. The script was retired instead (moved to `scripts/archive/`, with a header documenting it's a completed one-time script, not to be rerun without a v2 retarget + dedup fix), which cleared the blocker. A second authority-check pass then confirmed zero live references to any of the four legacy files, and all four were moved to `data/archive/` with a README and a CLAUDE.md guard-rail note added. A follow-up lightweight Reviewer spot-check confirmed the file moves, doc edits, and guard-rail note were all accurate and complete, and surfaced one additional pre-existing gap (now separately fixed): `moore-ops-updater`'s SKILL.md still listed the four archived files as valid Updater edit targets.

## Outcome

All recoverable Champs/Summer Awards history is now correctly loaded into the authoritative v2 files. The legacy files and the one-time script that (briefly, mistakenly) targeted them are archived/retired. A structural guard rail (the note at the top of the Data files section in Project Instructions/CLAUDE.md) and a process guard rail (Reviewer checklists must include file-authority checks, not just in-file correctness) are now both in place to prevent this specific mistake from recurring.
